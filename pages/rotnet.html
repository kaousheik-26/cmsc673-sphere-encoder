RotNet: guess how far, then guess which way

RotNet is shown only the first frame of a video and a time, and guesses where that later frame sits on the image encoder's sphere (every picture is a point on it; a video is a path). Instead of one arrow, it splits the guess into two answers: how far the frame has moved and which way. That lets us see exactly which half goes wrong.

Think of giving directions in a city: "walk 2 km" and "head north-east" are two separate facts. RotNet gets the distance nearly right. It gets the heading wrong.

Say it out loud: RotNet knows how far the video moves but not which way. Give it the right direction and its error drops from about 20 degrees to under 5.

Architecture

Input: first frame's latent \(z_0\)
frozen sphere encoder, 256 tokens × 384 numbers, on a sphere of radius √98,304 ≈ 313.5
↓
Linear 384 → 384 per token, + learned position
with the frame 2 hint the input is frame 0 and frame 2 side by side (768 → 384)
↓
4 transformer blocks, width 384, 6 attention heads
each block: adaptive LayerNorm (scale and shift set by time) → self-attention over the 256 tokens → adaptive LayerNorm → MLP 384 → 1536 → 384. Time modulation starts at zero.
↓
Direction head
Linear 384 → 384 per token, laid flat on the sphere at \(z_0\) (tangent projection), scaled to unit length: \(\hat d\)
Angle head
average over the 256 tokens, joined with the time vector, MLP 768 → 384 → 1, softplus × 10: \(\hat\theta\) in degrees
↓
Compose: rotate \(z_0\) by \(\hat\theta\) towards \(\hat d\)
$$\hat z_t=\cos\hat\theta\,z_0+\sqrt{L}\,\sin\hat\theta\,\hat d$$ At t = 0 the angle is 0, so frame 0 comes back exactly.
Time \(t=\text{frame}/80\) ∈ [0, 1]
sine/cosine code at many speeds → MLP → time vector \(c\). \(c\) sets the scale and shift inside every block and also feeds the angle head directly.
Where the targets come from
For each training pair, the true later frame \(z_t\) is split into a true angle and a true direction with the sphere's log map: $$\theta^*=\arccos\frac{\langle z_0,z_t\rangle}{L},\qquad d^*=\frac{z_t-\cos\theta^*\,z_0}{\lVert z_t-\cos\theta^*\,z_0\rVert}$$ So "how far" and "which way" each have their own right answer.
Sizes

The objective: two scores, added

$$\mathcal{L}=\underbrace{\frac{|\hat\theta-\theta^*|}{10^\circ}}_{\text{how far}}+\underbrace{1-\cos(\hat d,\,d^*)}_{\text{which way}}$$
  • How far: the gap between the guessed and true angle, in units of 10°. Missing by 1° costs 0.1.
  • Which way: 0 when the direction is exact, 1 at 90° off (a blind guess), 2 when it points backwards.
  • Exchange rate: 1° of distance error costs the same as 26° of direction error, so the model is pushed hard to get the distance right first.
  • Each training step: 64 random (clip, frame) pairs from the 24 training clips, average loss, AdamW. No image loss and no smoothness term.
  • True direction test: keep RotNet's own angle \(\hat\theta\) but swap in the real direction \(d^*\). This shows how good the video would be if only the direction were fixed.

What this means

    Setup: 24 training and 16 new 5 s clips (81 frames, 16 fps) from one text-to-video model, encoded by the sphere image encoder. Angle errors averaged over every frame after the first. RotNet and the hint version were trained for 4,000 steps; the 200k run continues RotNet from that point. Companion pages: FrameNet 10 M vs 106 M, FrameNet vs RotNet.
